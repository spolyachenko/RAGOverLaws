# Финальный сквозной отчёт: RAG-система по российским законам (КТ1–КТ5)

Система: корпус 2 218 документов (русская викисource + 12 внешних источников) →
dedup → 1 415 доков → TokenChunker(512) → 67 022 чанка → Qdrant + BGE-M3 →
HyDE + CE-реранк → генерация Qwen3.8-27B с инструктом «Не знаю». Оценка — gold100
(30 factual / 30 composite / 20 abstract / 20 negative), retrieval-метрики на val
(56 q с doc_ids), judge-метрики на всех 100.

## 1. Сводная таблица метрик по всем КТ

R@5/NDCG@5 — retrieval (gold val, top-40 чанков → уникальные документы).
Faithfulness/Relevance — LLM-judge (1–5) на сгенерированных ответах (только КТ5:
ранее ответов не было). Latency — retrieval-стадия для КТ3–4, end-to-end
(retrieval + генерация) для КТ5.

| конфигурация | R@5 | NDCG@5 | Faith | Relevance | latency |
|---|---|---|---|---|---|
| КТ2: BM25 (дефолт) + token512 | 0.411 | 0.330 | — | — | 122 мс |
| КТ3: Qdrant + BGE-M3 (baseline) | 0.768 | 0.644 | — | — | 94 мс |
| КТ4: +HyDE | 0.804 | 0.735 | — | — | 2.1 с |
| КТ4: +CE pool 20 | 0.821 | 0.687 | — | — | 144 мс |
| КТ4: +HyDE+CE (best) | **0.857** | 0.680 | — | — | 2.36 с |
| КТ5: генерация, ретрив = КТ3 | 0.768 | 0.644 | **4.81** | **4.68** | 1.7 с e2e |
| КТ5: генерация, ретрив = КТ4 best | 0.857 | 0.680 | **4.82** | 4.57 | 4.1 с e2e |

Читаем таблицу так: BM25→dense (+0.357 R@5, КТ2–3) и CE (+0.053, КТ4) двигают
retrieval; HyDE двигает NDCG/MRR (ранжирование) меньше, чем R@5. Переход КТ4→КТ5
(лучший ретрив → генерация) **не двигает** judge-метрики: 4.82/4.57 против
4.81/4.68 — генератор сжимает разницу ретриверов. И обе judge-оценки завышены:
судья ставит R=5 на ложных отказах (ответ не виден в топ-5 контексте), реальная
ответимость — 40–42% (§2).

## 2. Анализ bottlenecks

**Где система теряет больше всего качества — на поиске или генерации?**
На генерации: best-ретрив лучше baseline на +0.089 R@5 и +0.143
hit@1, но на сгенерированных ответах judge не видит разницы (ΔF 0.01, ΔR −0.11
в пользу baseline). Потери генератора: (а) на 80 ответимых (non-negative)
вопросах дан ответ только к **40–42% (32–34 из 80)**; 58–60% — ложные отказы
(ответ в корпусе есть, но не в топ-5 контексте); судья их не ловит (R=5 на 44/48
и 38/46 таких отказов), реальную ответимость дал только ручной прогон; (б) в КТ1
та же модель без RAG ни разу не отказала (0/100) — инструкция без контекста
не работает, с контекстом — переглушена. Поиск теряет меньше и
предсказуемо: best R@10 = 0.893, т.е. ~11% вопросов остаются не найденными даже
лучшим ретривом (пример: «14 дней на возврат» — нужная норма не попала в top-5 ни
у одной конфигурации, обе провалили вопрос).

**Какие типы вопросов система не научилась обрабатывать хорошо?**
1. **Abstract** («почему…», «как суды обычно смотрят…»): R 4.35 (best), отказы,
   «на 'почему' не отвечено» (ручная оценка). Модель либо отказывает, либо даёт
   общие нормы без объяснения.
2. **Composite с несколькими компонентами** (маткапитал + ипотека + доли детей):
   модель роняет компоненты — «ипотека не разобрана», «ст. 38 применена не к месту»
   (ручная оценка); R 4.37–4.50.
3. **Negative с ложной предпосылкой** («развод через суд присяжных»): отказ
   корректный (20/20), но ложная предпосылка не оспаривается.
4. **Factual на грани top-5**: точная норма (цифра/срок) не в пяти чанках → ошибка
   или отказ (14 дней vs 3 месяца).

**Что дало наибольший прирост качества на единицу усилий?**
1. **BM25 → dense BGE-M3** (КТ2/3): +0.357 R@5 (0.411 → 0.768). Усилие — сменить
   ретривер на готовый. Крупнейший скачок проекта.
2. **«Не знаю» + контекст** (КТ5): 0/100 → 20/20 корректных отказов на negative.
   Усилие — одна строка промпта + наличие контекста. Качественный сдвиг
   faithfulness (галлюцинации КТ1 исчезли: judge F 4.81–4.82); цена — ложные
   отказы на 58–60% ответимых вопросов (см. §2).
3. **CE-реранк pool 20** (КТ4): +0.053 R@5 за +50 мс и 0 токенов — лучшая цена/
   качество внутри retrieval-части.

## 3. Выводы по каждому КТ + план развития

**КТ1.** Сработало: EDA выявила структуру мусора (13.2% junk, 36% дублей редакций),
gold100 с verbatim-проверкой контекстов. Не сработало: ничего критичного.
Неожиданность: модель no-RAG с явной инструкцией «отвечай только по тексту»
ни разу не сказала «не знаю» (0/100) — инструкция без контекста не работает.

**КТ2.** Сработало: dedup (главный выигрыш, −36% объёма), dense-сквозной результат
0.411 → 0.768. Не сработало: LLM-суммаризация (110M токенов на корпус, +0.018),
parent/child на уровне документов (ничего не дал). Неожиданность: чанкер важен
только для BM25 (sentence/semantic +0.05), для dense token512 оптимален —
«лучший чанкер» зависит от ретривера.

**КТ3.** Сработало: Qdrant local (на 67k ANN = exact: 0.768 у всех конфигов,
разницы в латенси <3 мс), BM25-грид (k1=2.0/b=0.75). Не сработало: hybrid RRF
(0.714 < 0.768 — BM25-шум только разбавляет dense). Неожиданность: MTEB-ранг
не переносится на корпус: instruct-модель gte-Qwen2 (топ MMTEB) показала худший
результат (0.482) — режим промптинга важнее размера.

**КТ4.** Сработало: HyDE (+0.036 R@5, MRR 0.613 → 0.725, помогает composite/
abstract), CE pool 20 (+0.053 R@5, качество плоское от pool=20), LLM-rerank
детерминирован (top-1 20/20 при temp=0). Не сработало: score-порог CE (плоская
кривая, потом обвал), hybrid-пул для CE (не лучше dense-пула), pointwise
(хуже listwise и в 10× дороже). Неожиданность: top-20 dense уже содержит всё
релевантное — больший пул лишь добавляет латенси.

**КТ5.** Сработало: механизм «Не знаю» (20/20 на negative, подтверждено
человеком), judge v2 (двойные прогоны 96.7–100% agreement; на содержательных
ответах κ=0.67 (relevance) и 0.63 (utilization) vs человек). Не сработало:
конвертация лучшего ретрива в качество ответов (F/R/U равны). Неожиданность:
(1) инструкция «Не знаю» переглушена — 58–60% ответимых вопросов получило
отказ (48/80 и 46/80); (2) судья слеп к ложным отказам (R=5: ответ не виден
в топ-5 контексте) — judge-метрики без ручной валидации завышены.
Bottleneck системы — генератор (ответимость), а не поиск.

### План развития (приоритет по данным)

**P1. Смягчить инструкцию отказа + контекст top-10** (дешевле всего, бьёт в главный
bottleneck). Данные: ответимость 40–42% (32–34/80), ложные отказы 58–60%
(48/46), best R@10 = 0.893 (top-5 = 0.857 — есть что добавлять), ручная оценка:
«отказ честный, но в пояснении сроки смешаны». Промпт: «отвечай, если в контексте есть
хотя бы релевантная норма; "Не знаю" — только при полном отсутствии; указывай
ложные предпосылки в вопросе». Усилие: 1 итерация промпта + перегон 200 ответов
(~20 мин LLM) + judge. Ожидаемо: +15–25 п.п. ответимости, рост judge-R за счёт
содержательных ответов.

**P2. Домен-адаптация эмбеддера/CE на юридических парах** (средняя стоимость:
~2 ч GPU + подготовка пар из gold). Данные: КТ3 — расхождение MTEB-ранга с
корпусным качеством (instruct-модель просела), КТ5 — провалы «точной нормы»
(14 дней не в top-5), abstract R 4.35. Формулировка: fine-tune bge-m3 (или
CE) на (вопрос, релевантный чанк) парах из gold100 + расширенных доков.
Ожидаемо: R@5 0.857 → ~0.9, меньше «соседних статей» в топе.

**P3. Кросс-документное рассуждение для composite/abstract** (дороже всего:
агент с многошаговым поиском или граф закон→статья→тема). Данные: composite
роняет компоненты (ручная: «ипотека не разобрана», R 4.5), abstract «почему»
без ответа (R 4.35, 17/20 отказов у best), negative с ложной предпосылкой
не оспаривается (R 2 по ручной оценке). Целевые — 30–40% самых сложных
вопросов; начинать после P1/P2, на которые они не влияют.
